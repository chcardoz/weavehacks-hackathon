## `keepalive.watchdog(...)`

A context manager wrapping a `Watchdog`. This is **door 1** — the in-process path. It
installs a metric hook on `run.log()`, so soft failures are caught with zero polling lag,
and runs the full incident flow when one fires.

```python
import wandb
import keepalive

run = wandb.init(project="my-model")

with keepalive.watchdog(run, escalate=["sms"], timeout=120, checkpoint_dir="ckpts/"):
    for step in range(num_steps):
        loss = train_step()
        run.log({"loss": loss}, step=step)
```

### Parameters

These mirror the `Watchdog` constructor. The common ones:

| Parameter | Type | Default | Description |
| --------- | ---- | ------- | ----------- |
| `run` | `wandb.Run \| None` | `None` | The active W&B run to monitor. The metric hook is installed on its `log()`. |
| `settings` | `Settings \| None` | `None` | Explicit `Settings`; falls back to `Settings.from_env()`. |
| `checkpoint_dir` | `str` | `"checkpoints"` | Directory of checkpoints probes resume from. **Required for recovery.** |
| `timeout` | `float \| None` | `None` | Escalation deadline in seconds. `None` → `settings.escalation_timeout_s` (120). |
| `escalate` | `Sequence[str]` | `("sms",)` | Escalation channels. |
| `loss_key` | `str \| None` | `None` | Metric key treated as loss. `None` → `settings.loss_key` (`"loss"`). |
| `entrypoint` | `list[str] \| None` | `None` | Command used to launch probe runs (defaults inferred). |

### Injectable collaborators (advanced / tests)

Every external client is injectable, so you can stub them in tests or swap
implementations: `executor`, `suite`, `engine`, `escalation`, `deadline`, `memory_`,
`router`, `bus`, `cursor`. Leave them `None` to use the defaults built from `Settings`.

To use a custom probe runner, pass `executor=`. See
[executors](/reference/executors).

### `Watchdog.handle_failure(event: FailureEvent) -> None`

Runs the full incident flow for a detected failure: diagnose → escalate → await reply or
timeout → probe race → promote. It raises one of the control exceptions below to tell your
loop what to do. The context manager calls this for you; call it directly only in custom
integrations.

## Control exceptions

The flow signals your code by raising. All inherit from `KeepaliveError`. Catch them
**outside** the `with` block — the watchdog re-raises them as it exits.

| Exception | Raised when | Attributes |
| --------- | ----------- | ---------- |
| `KeepaliveStop` | Human replied **3**, or training should halt. | — |
| `KeepaliveRollback` | Human replied **1**. | `.checkpoint: str \| None` |
| `KeepaliveHandedOff` | Authority transferred and a probe won the race. | `.incident: Incident`, `.winner: ProbeResult` |

```python
from keepalive import (
    watchdog,
    KeepaliveStop,
    KeepaliveRollback,
    KeepaliveHandedOff,
)

try:
    with watchdog(run, checkpoint_dir="ckpts/"):
        train()
except KeepaliveRollback as e:
    load_checkpoint(e.checkpoint)
    # resume from the last good checkpoint
except KeepaliveHandedOff as e:
    print(f"probe {e.winner.spec.id} took over; trace: {e.incident.trace_url}")
    # the winning probe's run is now your training
except KeepaliveStop:
    print("training stopped by request")
```

<Note>
`KeepaliveHandedOff` carries the full `Incident` (including `trace_url`) and the winning
`ProbeResult` — everything you need to continue from the promoted run or report it.
</Note>
