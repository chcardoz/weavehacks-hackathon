## 1. Install

```bash
pip install keepalive
```

## 2. Get an API key

Sign in at [keepalive.club](https://keepalive.club), issue a key, and copy it — it's
shown **once**. Keys are prefixed `ka_live_`.

The key authenticates with the keepalive relay, which now manages the OpenAI bits for you:
it relays Telegram (send + reply webhook), synthesizes and hosts the voice note, and proxies
the diagnosis LLM. So you don't bring your own OpenAI key. Detection, diagnosis orchestration,
and probes all run locally on your GPU box.

## 3. Connect Telegram

Open the keepalive bot in Telegram — [t.me/keepalive_bot](https://t.me/keepalive_bot) — and
press **Start**. The bot replies with your chat id and the exact env line to copy:

```
KEEPALIVE_TELEGRAM_CHAT_ID=<your-chat-id>
```

<Note>
You **must** press Start at least once. A Telegram bot cannot message a user who has never
started a chat with it.
</Note>

## 4. Set environment variables

keepalive reads its configuration from the environment. The setup is two keys you already
have (W&B, Cursor) plus your keepalive key, then press Start on the bot:

```bash
export KEEPALIVE_API_KEY="ka_live_..."           # from the dashboard
export KEEPALIVE_TELEGRAM_CHAT_ID="..."           # from the bot's Start reply
export WANDB_API_KEY="..."                        # W&B metrics + Sandboxes auth
export CURSOR_API_KEY="..."                       # Cursor cloud agents write the fixes
```

`KEEPALIVE_API_URL` defaults to `https://api.keepalive.club`, so you only set it when
self-hosting the relay.

<Note>
No `OPENAI_API_KEY` and no `REDIS_URL` required. The relay handles diagnosis-LLM calls and
TTS for you. Redis is opt-in (power-user / self-host); without it keepalive uses an
in-process deadline timer and the core incident flow is unchanged. See the
[configuration reference](/reference/configuration) for every variable and its default, and
[Cursor onboarding](/probes#cursor-onboarding) for the one-time Cursor setup.
</Note>

## 5. Wrap your loop — door 1 (context manager)

The primary path. Wrap your hand-rolled PyTorch loop. keepalive installs an in-process
hook on `run.log()`, so failures are caught with zero polling lag.

```python
import wandb
import keepalive

run = wandb.init(project="my-model")

with keepalive.watchdog(run, escalate=["telegram"], timeout=120, checkpoint_dir="ckpts/"):
    for step in range(num_steps):
        loss = train_step()
        run.log({"loss": loss}, step=step)
        if step % 100 == 0:
            save_checkpoint(f"ckpts/step{step}.pt")
```

When a soft failure (NaN, divergence, stall, exception) is detected, the watchdog pauses,
diagnoses, escalates, and — depending on your reply or the timeout — raises a control
exception you can catch. See the [watchdog reference](/reference/watchdog#control-exceptions).

## 6. Or supervise a subprocess — door 2 (CLI)

When you can't (or don't want to) edit the loop, run your script under the supervisor.
This survives **hard** crashes (CUDA OOM, segfault) that kill the process, by tailing
stderr and polling W&B history.

```bash
keepalive run -- python train.py --epochs 10
```

Everything after `--` is your command, run verbatim. See the [CLI reference](/reference/cli).

## Checkpoints are required

keepalive resumes probe runs from your **last good checkpoint** — that's how it can race
fixes without restarting from scratch. Checkpointing is a hard requirement, and we say it
proudly: everyone running serious training already checkpoints. Point `checkpoint_dir` at
the directory you write to, and keep writing checkpoints on your normal cadence.
